# 18. 승인 무효화: 승인 뒤 바뀌면 보내지 않는다

> 작성 2026-11-03 · 담당 서준영(B) · 노션 할 일 "승인 무효화" (끝 기준: 승인 뒤 변경 시 전송 안 됨 테스트 통과)
> 구현 `GatewayService.dispatch()` · 시험 `ApprovalInvalidationTest`

## 1. 규칙

승인자가 승인하는 것은 **요청을 만들 때 평가하고 화면에 보인 그 조건**이다. 보내기 직전에 조건을 다시 계산해서, 하나라도 다르면 보내지 않는다.

**승인 지문** = SHA-256(파생본 해시 | 목록 버전 | 전송 대상 | 대상 등급 | 정책 규칙 버전)

| 지문에 든 값 | 승인할 때 (만들 때 값) | 보내기 직전 (지금 값) | 이런 경우를 막는다 |
| --- | --- | --- | --- |
| 파생본 해시 | 저장된 해시 | 지금 파생본을 다시 해시 | 저장소에서 파생본을 바꿔치기한 경우 |
| 목록 버전 | 만들 때 목록 버전 | 지금 담기 목록 내용의 해시 | 승인 대기 중에 담기 목록을 고친 경우 |
| 전송 대상 | 요청의 대상 ID | (같은 값. 바뀌면 등급이 달라져 걸린다) | 대상을 다른 곳으로 바꾼 경우 |
| 대상 등급 | 만들 때 등록부에서 읽은 등급 | 지금 등록부의 등급 | 대상이 T1에서 T2로 옮겨지거나 등록에서 빠진(T0) 경우 |
| 정책 규칙 버전 | 만들 때 쓴 규칙 버전 | 지금 서버의 `PolicyEvaluator.POLICY_VERSION` | 예전 규칙으로 평가된 요청을 새 규칙 서버에서 승인하는 경우 |

- 지문이 다르면 상태는 `SEND_FAILED`가 되고, 감사 기록에 `FINGERPRINT_MISMATCH`와 **무엇이 바뀌었는지**(예: `대상 등급 T1→T0`)를 남긴다. 값 자체는 남기지 않는다.
- 끝난 요청은 다시 승인할 수 없다(409). 바뀐 조건으로 보내려면 새 요청을 만들어 다시 평가와 승인을 받는다(D11).
- 승인 없이 보내는 길(조건부 승인)도 같은 지문 검사를 거친다.
- 등급이 더 안전한 쪽(T1→T2)으로 바뀌어도 막는다. 승인자가 본 조건과 다르기 때문이다.

이번 변경 전에는 지문에 대상 등급과 정책 규칙 버전이 없었다. 그래서 승인 대기 중에 대상이 등록에서 빠지거나 규칙이 바뀌어도 승인하면 그대로 나갔다.

모든 실패 경우에 AI 답이 비어 있고 `SENT` 기록이 없는 것까지 확인했다. 시험의 AI는 mock이라 외부 호출이 없다.

## 3. 남은 빈틈

- 같은 등급의 다른 등록 대상으로 대상 ID만 바꾸면(예: T1 둘 사이) 지문은 같다. 지금은 등록 대상이 하나이고, 전송 직전에 대상이 실제 AI 공급자와 같은지 한 번 더 확인하므로(`ENDPOINT_REJECTED`) 막힌다. 대상이 여럿이 되면 만들 때 지문을 따로 저장해 비교해야 한다.
