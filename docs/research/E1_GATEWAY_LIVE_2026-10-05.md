# E1. 게이트웨이를 거친 실제 AI 전송 (2026-10-05)

## 무엇을 확인했나

망을 분리한 상태에서, 내부 서버가 게이트웨이를 거쳐 실제 외부 AI(gpt-5.1)로 장애 로그를 보내고 답을 받는 전체 흐름이 동작하는지, 그리고 그 답이 파일럿(9/29, 담기 10칸)과 같은 수준인지 확인했다.

## 방법

- 환경: `docker-compose.gateway.yml` (내부망은 인터넷 차단, 게이트웨이만 두 망에 연결), colima-pilot, `YG_AI_MOCK=false`
- 모델: `gpt-5.1-2025-11-13`, temperature 0, 고정 질문 (파일럿과 같은 `AiClient`)
- 입력: 파일럿과 같은 전처리 로그 `scenarios/{S1,S2,S3,S6}/raw.jsonl`
- 흐름: 내부 서버(`internal-client`)에서 `ops-kim`이 요청 → `sec-park`가 화면에서 본 파생본 해시로 승인 → 게이트웨이가 지문 확인 뒤 전송
- 각 1회. 원본 응답은 `experiments/yeogwasigan-spring/results/e1_gateway_live_20261005/` (git 제외)

## 발견: 담기로 남은 본문 속 민감값과 참고 경고

S1 파생본의 `body` 한 줄에 실험에서 넣어 둔 값(`user.id`, `user.email`, 카드번호)이 남아 있었고, AI가 답에 그 문장을 그대로 인용했다. 칸 단위 담기로는 본문 속 값을 막을 수 없다는 기존 한계가 실제 전송에서도 확인됐다.

같은 요청에서 게이트웨이의 참고 경고가 EMAIL 1, UUID 1, CARD 1을 표시했다. 승인자가 이 경고를 보고 반려했다면 나가지 않았다. 이번에는 흐름 확인이 목적이라 그대로 승인했다. 참고 경고가 실제로 쓸모 있다는 근거이면서, 승인자가 경고를 놓치면 새어 나간다는 한계이기도 하다.

S2·S3·S6의 UUID·IPV4 경고는 대부분 본문 속 세션 ID와 Docker 내부 IP다. 경고가 많으면 승인자가 무시하게 되므로, 경고 기준을 다듬는 일이 남는다.
