# 학교 서버에서 여과은행 시연 보기

준수가 만든 여과은행 시뮬레이터(`experiments/network-demo/bank`)를 학교 클라우드(DKU Cloud) 회사 VM 에 올렸다.
팀원 누구나 **학교 VPN 만 켜면** 브라우저로 바로 들어가 볼 수 있다.

## 바로 가기 (학교 VPN 필요)

| 화면 | 주소 | 서버 |
|---|---|---|
| 여과은행 인터넷뱅킹 (손님 화면) | http://10.0.1.37:9001 | 회사 VM `yeogwa-company` :9000 |
| 여과은행 운영 모니터 (개발자 화면) | http://10.0.1.37:9300 | 회사 VM `yeogwa-company` :9300 |
| 여과시간 (걸러 내기 · 승인 · 감사) | http://10.0.1.37:8080/gateway.html | 게이트웨이 VM `yeogwa-gw` :8080 |

- 바깥 9000번은 다른 VM(node-a)이 이미 쓰고 있어서 인터넷뱅킹만 **9001** 로 열었다. VM 안에서는 그대로 9000 이다.
- 여과시간 계정: 요청자 `ops-kim`, 승인자 `sec-park`. 비밀번호는 단톡방에서 준영에게 물어본다 (저장소에 적지 않는다).
- 안 열리면 먼저 학교 VPN(OpenVPN)이 켜져 있는지 확인한다. 10.0.x 는 캠퍼스 안 주소라 VPN 없이는 안 열린다.

## 화면으로 해 보는 순서

1. **인터넷뱅킹(9001)**: 가상 손님이 초당 3건쯤 조회·이체를 하고 있다. 직접 로그인해서 이체도 해 볼 수 있다.
2. **운영 모니터(9300)**: 서비스 상태가 모두 정상, ERROR 0건인지 본다.
3. 모니터에서 **① 대외기관 멈추기** → 20초쯤 뒤 빨간 "장애 감지".
4. 모니터에서 **여과시간에 분석 요청** (최근 30초, 장애 원인 분석 목록) → `REQ-000N` 이 만들어진다.
5. **여과시간(8080)** 에 `ops-kim` 으로 로그인 → 방금 요청에서 버려진 칸, 실제로 나갈 내용 확인 → **승인 없이 전송** → AI 답.
6. 모니터에서 **④ 디버그 로그 켜기** + **① 대외기관 멈추기** → 다시 분석 요청 → 높음 경고가 떠서 승인 필요.
   `sec-park` 로 로그인해 사유를 쓰고 **반려** → 감사 기록에 REJECTED.
7. 끝나면 모니터에서 **↺ 모두 복구**.

자세한 장면 설명은 준수의 시연 설명 자료(여과은행_시연_설명_1110.pptx), 장애 4가지와 로그 형식은 [bank/README.md](../bank/README.md).

## 네트워크 구성 (DKU Cloud)

공인 IP `10.0.1.37` (Source NAT) 에 포트포워딩과 방화벽을 추가했다. 기존 구성은 [DKU_클라우드_구성.md](DKU_클라우드_구성.md).

| 바깥 포트 | → VM:포트 | 용도 |
|---|---|---|
| 2201 | yeogwa-gw:22 | 게이트웨이 SSH |
| 2202 | yeogwa-company:22 | 회사 서버 SSH |
| 8080 | yeogwa-gw:8080 | 여과시간 화면 |
| **9001** | yeogwa-company:9000 | 여과은행 인터넷뱅킹 (11/13 추가) |
| **9300** | yeogwa-company:9300 | 여과은행 운영 모니터 (11/13 추가) |

방화벽은 9001·9300 모두 학교 VPN 대역 `10.8.0.0/24` 와 `10.0.0.10/32` 에서만 들어올 수 있다. 인터넷 전체에는 열지 않았다.
계정계(9100)·대외기관(9200)은 VM 안에서만 쓰므로 열지 않았다.

회사 VM 은 11/9 에 다시 만들었고, 내부 IP 는 예전과 같은 `192.168.0.236` 으로 맞췄다.

## 서버 켜고 끄기 (SSH 키가 있는 사람만)

노트북 PowerShell 에서 학교 VPN 을 켠 뒤 접속한다. 키(`dku_yeogwa`)가 없으면 준영에게 공개키를 보내서 등록을 부탁한다.

### 게이트웨이 VM

```powershell
ssh -i $HOME\.ssh\dku_yeogwa -p 2201 ubuntu@10.0.1.37
```
```bash
cd ~/yeogwasigan && git pull
cd experiments/yeogwasigan-spring && ./gradlew bootJar -x test
export YG_DEMO_PASSWORD='시연용 비밀번호'
export YG_APPROVAL_MODE=CONDITIONAL
java -jar build/libs/yeogwasigan-0.1.0.jar     # SSH 를 끊어도 돌게 하려면 tmux 안에서
```

### 회사 VM

```powershell
ssh -i $HOME\.ssh\dku_yeogwa -p 2202 ubuntu@10.0.1.37
```
처음 한 번만:
```bash
sudo apt update && sudo apt install -y git
git clone https://github.com/ygsg-dku/yeogwasigan.git
```
켜기:
```bash
cd ~/yeogwasigan && git pull
cd experiments/network-demo/bank
./bank.sh reset                                   # 로그·원장을 지우고 처음 상태로
export YG_DEMO_PASSWORD='게이트웨이와 같은 비밀번호'   # 같아야 모니터의 보내기 버튼이 켜진다
export YG_GATEWAY_URL=http://192.168.0.138:8080    # 게이트웨이를 내부 주소로 부른다
export YG_GATEWAY_SCREEN=http://10.0.1.37:8080     # 모니터에 뜨는 여과시간 링크
./bank.sh start 3
./bank.sh status                                  # channel · core · kftc · monitor 가 pid 로 나오면 성공
```
은행은 백그라운드로 돌아서 SSH 창을 닫아도 계속 돈다. 끌 때는 `./bank.sh stop`.

- 예전 결제 시뮬레이터(`company/payment_service.py`)도 9000 포트를 쓰므로 둘을 같이 켜지 않는다.
- 모니터의 보내기 버튼으로 시연할 때는 전송기(`shipper.py`)를 같이 켜지 않는다 (같은 장애가 두 번 들어간다).
- 새로 만든 VM 이라 처음 접속할 때 `REMOTE HOST IDENTIFICATION HAS CHANGED` 가 뜨면 `ssh-keygen -R "[10.0.1.37]:2202"` 후 다시 접속한다.

## 안 될 때

| 증상 | 확인할 것 |
|---|---|
| 브라우저에서 아무 주소도 안 열림 | 학교 VPN 연결 |
| 8080 은 열리는데 9001·9300 이 안 열림 | 회사 VM 에서 `./bank.sh status` (꺼져 있으면 위 "켜기") |
| 모니터의 [여과시간에 분석 요청] 버튼이 회색 | 회사 VM 에서 켤 때 `YG_DEMO_PASSWORD` 를 안 넣었거나 게이트웨이와 다름 |
| 요청은 갔는데 여과시간 로그인 실패 | 게이트웨이를 켠 창에서 `YG_DEMO_PASSWORD` 를 export 했는지 |
